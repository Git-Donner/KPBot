# 通用性能测试重复测量与波动报告补充

## 交付范围

本目录是以本地 KPBot-master 为基准的增量文件包，不是完整可安装仓库。相同相对路径的文件为修改后的完整文件；未提供的文件沿用原仓库。请在新建的完整仓库副本或开发分支中覆盖这些文件，不覆盖保留用的 KPBot-master。

选择补充现有技能，而非新增测试入口：prepare-project 原本负责基线，verify-optimization 原本负责性能验收，缺口是重复测量规则没有贯穿默认流程。修改主编排器及其提示以保留计划和统计摘要，让用户无需额外提醒“多测几次”。保留原有命令、正确性、目标机器、隔离候选、预算和交付路由。

## 关键行为

- 预算允许的短测试默认每组计划 5 次；不是任意实验达到 5 次就可靠。用户次数/预算优先，昂贵或一次测试明确降级。
- 独立单元、预热、重置和提取方法在执行前固定。内循环、请求样本、代码修改轮次不能当作独立重复。
- 候选就绪后优先交错测量同条件基线/候选，前期基线和复测基线不混合。失败及异常保留，禁止挑最好结果或反复测到通过。
- 逐组逐指标输出 n、均值 ± 样本标准差、median、min/max、MAD、CV。n=1 不伪造零波动；±SD 不当作置信区间。
- 有限零/负值可描述统计，正数比值验收保留原约束。不同单位或工作负载不混合，不强制吞吐/时延字段名。
- 多 CSV/TSV/JSON 可合并；TXT/宽表先由 agent reshape。工具拒绝重复 run_id 和非有限值，保存原文件哈希与逐样本来源，不覆盖已有输出。
- 正确性仍独立验收；波动不足以支持结论时保持 inconclusive/unverified，报告原因而非仅给收益百分比。

## 用户如何使用与验收

先在完整测试副本上安装修改后的插件。准备真实项目、可运行的既定性能命令、父版本和候选版本、目标服务器身份。以下提示刻意不提醒“重复”，用于检验是否主动执行。

| 场景 | 给 Agent 的话 | 应观察到的行为/输出 |
|---|---|---|
| 自动建立基线 | “请用 prepare-project 准备这个项目，性能命令为……，目标服务器为……，总测试预算 10 分钟。” | 测试前声明计划；多次独立运行；基线 n、均值±SD、范围及 raw 引用 |
| 常规对比 | “请用 verify-optimization 验证这个候选，沿用上述项目命令。” | 保留测量计划；隔离父/候选交错执行；逐次日志与完整统计；不会只报一次加速比 |
| 明显噪声/小收益 | 在有实际波动的服务器执行同一请求，或提供已有波动日志请分析 | 主动指出变化与波动难区分，给 inconclusive；无预算时停止，不筛掉慢样本 |
| 多维多指标 | “比较三种实现、两种线程数，报告耗时、吞吐和 IPC，数据在这些文件中。” | 分组不混合，多文件 reshape 后计算；明确每指标方向和单位 |
| 内循环陷阱 | “该命令会输出进程内的 1000 次迭代，比较两个版本。” | 区分内循环与独立运行；不把 n=1000 当独立实验次数 |
| 单次预算 | “只允许每版本运行一次。” | 遵守次数，显示波动未知，不能判可靠提升/退化 |
| 超时或错误 | 某轮真实失败/超时或退出码非零 | 保留失败记录与已完成次数，不能用成功轮掩盖失败后通过 |
| 最终汇总 | “请总结本轮优化效果。” | 用户直接看到 n、均值±SD、范围和结论限制，不需要查看附件才能发现波动 |

验收需保留 Agent trace、实际命令/时间顺序、原始日志、计划版本和最终 JSON；不能仅靠提示中出现“重复”字样判断成功。真机不应人为制造生产负载干扰；优先在隔离测试机观察自然波动。
